## Client onboarding slice

`ClientOnboardingPage(session:, onCompleted:)` reads `/api/v1/onboarding/status` and resumes authoritative stage/section. Stage 0 explains email verification; stage 1 displays the exact React StageTerms.tsx MSA v1.0 and requires explicit checkbox/click before POST terms. Stage 2 truthfully blocks excluded mobile Razorpay checkout and asks users to refresh after existing checkout/offline verification. No payment bypass or acceptance is inferred.

Stages 3–7 load saved questionnaire A–G, preserving unknown fields and untouched values. Known scalar/list/repeated-object fields map to the original StageQuestionnaire.tsx keys. Source-backed enum choices are used for category, primary goal, language/script, visual direction, on-camera people, shoot locations, exclusions, price band and guidelines. Some ancillary choices remain plain text. React A–E required validation runs before completion; section drafts may be saved incomplete. Native PNG/JPG/SVG logo upload uses existing document picker/multipart transfer and the actual <=10MB backend endpoint; removal uses confirmed DELETE and clears both saved/draft logo keys to avoid resurrecting a removed logo. Meta OAuth section H remains missing. Upload/save/terms/generation/completion results are never automatically retried when ambiguous.

Optional `/brand-dna/status` failures do not hide the questionnaire. Brand generation is explicit, with no fake polling or ready state. Completion requires server `status=completed` followed by GET status `is_complete=true` before the host callback. The host restores session/user state before entering portal. Logout remains enabled during pending work and generation checks prevent publishing ended-session responses. Nested row structural changes rebuild field state to prevent stale values after removal.

Five focused onboarding tests pass: unknown-field preservation/no invented defaults plus logout rejection; explicit terms consent; truthful payment blocking; resumed questionnaire at 320px despite optional brand-status404; unverified saves blocked across reopened repositories.
